Python / Flask + PostgreSQL Database Schema and Development Guide
Based on: RPMS_Proposal_Khmer_Updated_Flask_React.pdf (7 pages). The source proposal outlines the modules and 21
named tables; this document expands the columns and adds five recommended supporting tables.
PROJECT SUMMARY
Scope: Property setup, reservations, tenants, rental contracts, deposits, move-in inspections, utility meters, monthly
invoices, partial payments, maintenance, renewals, move-outs and refunds.
Management layers: TPS for transactions, MIS for occupancy/revenue/outstanding reporting, and DSS for price
simulations and forecasting.
Python-focused adaptation: Flask + Jinja2 templates + SQLAlchemy + PostgreSQL. The original proposal instead
specifies React/Vite for frontend; replacing it with Jinja2 is a recommendation to reduce separate JavaScript application
development.

DATABASE RELATIONSHIPS
• properties 1:N floors; floors 1:N rooms; rooms 1:N reservations and rental_contracts over time.
• rental_contracts N:M tenants via contract_tenants; rental_contracts 1:N invoices; invoices 1:N invoice_items.
• payments N:M invoices via payment_allocations; rooms 1:N utility_meters; utility_meters 1:N meter_readings.
• rental_contracts 1:N room_inspections and contract_renewals; rental_contracts 1:1 or 1:N deposits according to
deposit policy; deposits 1:N deposit_transactions.
• users N:1 roles; roles N:M permissions via role_permissions.
KEY CONSTRAINTS & BUSINESS RULES
• Prevent overlapping active lease periods and conflicting confirmed room reservations. Use a PostgreSQL exclusion
constraint or transaction-safe conflict check.
• Unique room identifiers per floor: (floor_id, room_number). Unique floor numbers per property: (property_id,
floor_number).
• Unique contract_tenants pair (contract_id, tenant_id) and role_permissions pair (role_id, permission_id).
• For monthly invoices, prevent duplicate non-voided invoices for the same contract and month (partial unique index).
• Disallow meter readings below the preceding reading except an explicitly approved meter replacement.
• Snapshot unit rates on meter_readings and agreed rent on contracts/invoice items to preserve historic billing.
• Allocate only confirmed payments; allocation totals may not exceed confirmed payment amount or invoice due,
unless a separately defined credit workflow exists.
• Manage deposit funds separately from recognized rental income. Track approvals and document refunds/deductions.

PYTHON TECHNOLOGY STACK
• Python 3 + Flask: application server, routes, Blueprints and business services.
• Jinja2 + HTML/CSS/Bootstrap: Python-friendly server-rendered frontend (adaptation from original React proposal).
• PostgreSQL + SQLAlchemy + Flask-Migrate: relational data, ORM and database migrations.
• Flask-Login (or equivalent) + RBAC: authentication and granular roles/permissions.
• Pandas/NumPy + Plotly/Chart.js: MIS/DSS calculations, trends, simulation and charts.
• Pytest + Docker Compose + Nginx: tests, containerized deployment and HTTPS reverse proxy.
IMPLEMENTATION PHASES
1. Analysis and schema: Requirements, ERD, SQLAlchemy models, migrations, login and roles.
2. Core management: Property/floor/room, tenant, reservation, contract and deposit.
3. Billing and operations: Inspections, utilities, invoice generation, payment allocation, maintenance, renewals and
move-out.
4. Intelligence and deployment: MIS dashboard, DSS pricing simulator, forecast, tests, Docker/Nginx, backup and
restore.
